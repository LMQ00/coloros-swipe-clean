## 0. 一句话

ColorOS / realme UI 的「划卡（recents swipe）杀不杀」白名单 LSPosed 模块（Kotlin）：按应用选择划卡后进程保留还是强制结束，覆盖系统内置白名单；**应用分身（多开）可单独设置**。规则见 [`AGENTS.md`](../AGENTS.md)，能力判据见 [`docs/testing.md`](testing.md)。

## 1. 最短上手路径

1. [`AGENTS.md`](../AGENTS.md)（会话自动加载）——规则、不可协商项、文档索引
2. [`docs/architecture.md`](architecture.md)——模块由哪些部分组成、5 个 Hook 挂在哪、配置数据怎么流
3. [`docs/testing.md`](testing.md) §步骤 1–5——跑一遍：CI 构建 → 安装 → 基线检查 → 配置生效 → 真机划卡
4. 要动手改代码前，先看 [`docs/architecture.md`](architecture.md) §常见改动 → 改哪里

## 4. 未做 / 已知缺口

| 缺口 | 说明 | 细节 |
|---|---|---|
| 系统应用分支 | `G0()` 把 `procDetailInfo.system == true` 的应用交给 `I0()`，该分支不经过 `getStopType`；模块不覆盖 | [`docs/references.md`](references.md) |
| 最近任务里手动锁定的卡片 | 由 `isRecentLockTask` 保护，模块不覆盖 | [`docs/references.md`](references.md) |
| 同一 userId 下同包多任务 | athena `J0()` 检测到该包还有其它任务会跳过整段处理；本体与分身是不同 user，**不受影响**。属系统既有行为，模块不介入 | [`docs/references.md`](references.md) |
| 无 launcher 入口的分身应用 | 分身枚举走 `LauncherApps`，只覆盖带 `MAIN`/`LAUNCHER` 的包，不列出 | [`docs/architecture.md`](architecture.md) §应用分身 |
| 模块 App 开机自动启动 | ColorOS 开机窗口闸门（`isPreventBootStartData` / `BOOT_PREVENT_START_APPLIST`）的**实际调用点未定位** `[待确认]`；当前用 Hook 侧缓存绕过，功能不受影响 | [`docs/references.md`](references.md) |
| 自动化测试 | 无任何单元 / 集成测试，验证全靠实机 + CI 构建 | [`docs/testing.md`](testing.md) |
